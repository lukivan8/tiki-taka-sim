# KD Verticalis

Команда построена вокруг одного измеренного факта об арене: **вратарь берёт
центральные удары и не берёт удары из широкой глубокой позиции.**

## Почему так

Вратарь — детерминированный рефлекс на каждом кадре 60 Hz, а не вероятность:

| Предел (из `arena/arena.yaml`) | Значение |
|---|---|
| Реагирует, только если мяч летит в створ | ±4.66 м |
| Задержка реакции | 0.18 с |
| Поперечная скорость / предел смещения | 7.5 м/с / ±4.2 м |
| Спасает радиусом на своей плоскости `x=50` | 2.15 м |

Из точки `(44, -12)` удар в центр створа пересекает плоскость вратаря около
`y = -6`, долетая за ~0.30 с. За вычетом реакции у вратаря остаётся ~0.12 с — он
успевает сместиться примерно на метр из нужных шести. Гол.

Тот же удар с `(48, 0)` вратарь берёт: мяч идёт прямо в него.

## Что отличает эту команду от baseline

| | nova-baseline | KD Verticalis |
|---|---|---|
| Условие `SHOOT` | дистанция ≤ 35 м и створ виден | расчёт рефлекса вратаря: удар должен забивать |
| Куда бьют | «открытое направление» | `ЛУЧШЕЕ НАПРАВЛЕНИЕ` с максимальным запасом |
| Позиция форвардов в атаке | якорь `ball.x + 13`, редко доходит до линии удара | карманы `(44, ±12)` сразу за середину поля |
| Ролевые зоны форвардов | `x ≤ 50`, `\|y\| ≥ 5` | расширены, чтобы карман был достижим |
| Приоритет паса | сохранить владение | доставить мяч в карман |

Baseline проигрывает не потому, что плохо играет, а потому что бьёт по признаку
«вижу ворота». Модель признаёт такой удар допустимым, вратарь его отражает,
и владение отдаётся сопернику.

## Проверка модели

Модель удара сверена с физикой симулятора на сетке позиций, направлений и
стартовых позиций вратаря:

- **0 ложных срабатываний** — `SHOOT` никогда не предлагается там, где вратарь
  спасает. Ошибки только в консервативную сторону.

## Где настраивать

- `shared/perception.py` — `shot_quality`, `best_shot`, `shooting_pocket`,
  `dynamic_anchor`.
- `strategy.md` — общий замысел.
- `players/*/role.md`, `situations.md`, `player.yaml` — роли.

```bash
make test-nova
```
